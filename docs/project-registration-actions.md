# 0.1.16：打开目录与移除工程登记

本片补正常 `companion-workspace` 模式中的两项原工程卡动作，只在 dot 做源码与 fake / jsdom 测试。没有真实目录打开、DELETE、Windows操作或部署；独立只读、配置编辑、问答和 Picker 构建不注册这些动作。用户的完整迁移目标仍未完成。

## 原证据与固定合同

使用已核原 v148 自有源码闭包；这两管理接口尚未声称 v150 现场实测。与已另核的 v150 状态 / Creator 生命周期合同分别记录。

| 动作 | 原路径与回复 | 原实现位置 |
| --- | --- | --- |
| 打开目录 | POST `/api/projects/:id/open-folder`，原UI空JSON；200 `{ok:true,path:登记路径}` | `mcp/src/companion/http-server.ts:429–433`、`companion-daemon.ts:363–367`、`companion/platform.ts:22–57`；原 `web/src/app.ts:3406–3416` |
| 移除登记 | DELETE `/api/projects/:id`，无body；200 `{removed:boolean}` | `http-server.ts:416–420`、`companion-daemon.ts:286–291`；原 `web/src/app.ts:3377–3387` |

原浏览器鉴权仍为同源Cookie、127.0.0.1 Host及非GET严格Origin。没有读写token、代理、扩CORS、强制/路径参数或新权限。open-folder的未知ID由requireProject产生普通500，并非404；DELETE不存在ID返回removed:false。普通错误不直接回显；403只有精确Forbidden可识别前置拒绝，其余不猜动作未执行。

打开目录仅发送ID，后台requireProject取原路径，检查access/stat后调用系统open / explorer.exe / xdg-open。spawnDetached下一次setImmediate确认，不等待退出码或窗口视觉。前端只接受严格 `{ok:true,path}`，4096字符以内绝对本地路径，保留原字节并与冻结路径相等校验。回执不同路径或隐私过滤需改写时保持UNKNOWN，不展示成目标已打开。

## 移除不是删工程，也不是可撤销事务

原动作依次执行：

1. 清内存Bridge路由缓存。
2. 从用户数据目录projects.json删除登记并重写。
3. 仅removed=true时，清tool-presets.json中的该工程选择并重写。

不删除工程文件、不停Creator/Preview、不卸载Bridge、不移除Dashboard工程/MCP客户端配置、不删预设定义，也不清调用历史/日志。原后端允许移除运行中工程；本页不会暗中先停进程。

两个文件并非原子事务，也没有整体回滚。登记已删而工具绑定清理失败可返回500；再次DELETE得到removed=false会跳过绑定清理，不能当修复。router也可能先被清而登记写失败。回复removed=false仅表示本次没有移除登记记录，不证明此前动作或绑定结果。

原POST登记可按规范路径再建ID，但不是undo：旧字段/版本重检测，已清绑定不自动恢复，原缺省工具范围为full，可能扩大可见工具范围。此片没有自动重新添加、补删、预设分配或恢复按钮。项目Git检查点不保护后端用户数据文件。

## 前端安全与可用交互

- 两动作复用现有Creator操作通道、provider、一次确认和全局单飞，不另建可与启停并发的writer。历史类型文件名保持兼容。
- 正常卡片展开区有“打开目录”“移除登记”；先冻结完整ID、名称、路径、版本、来源和快照时间，再以动作专属确认发送。运行状态未知不阻止已确认的登记管理；它不被当已停止。
- 移除确认明示非原子、无一键撤销、可能部分完成、预设绑定清除与以后full缺省风险。原UI没有确认，新增确认是前端防误触层，不宣称原后端有事务/撤销。
- 成功只保留回执并另读原登记与状态，不乐观删卡或篡改Creator状态。removed=true后原行消失，仍显示冻结目标与回执。removed=false保留布尔false。
- UNKNOWN / 报告失败不会自动重发或恢复登记。管理动作需要结果之后新发起并成功完成的登记回读；原生命周期仍要求新的真实运行状态。旧在途读取不能解除屏障。
- 最后移除回执有“重读登记与状态”。仅原连接可用；来源切换/断开后失效，不把A→B→A重新接通当旧会话继续。正常模式此读取也探Bridge，可能更新后台状态/日志，不能称零副作用。
- 回读单独显示原登记存在、缺失或同ID信息变化，永远不把UNKNOWN升级成成功。登记缺失不能证明由本请求造成，也不能证明工具绑定已清理。
- 关闭/离页/取消只停止前端等待；迟到响应不改旧结论。传输实际清理前阻止所有其他动作，清理失败保持阻断。来源/工程变化或新的手动快照撤销未发送确认。
- 保护只在本页内存；刷新丢失，原后端无operationId、跨tab CAS/fence或持久幂等。不能承诺跨页面恰好一次。再次操作须新确认。
