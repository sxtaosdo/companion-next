## 3. 三层规范如何分工

### 项目美术基准

跨资源共享：通过适用Canon Interface继承的美术定位和风格来源、项目内容说明、色彩用途、材质表达、光照方向/软硬与阴影、相机/透视原则、线条/细节密度、轮廓和可读性原则、命名规则、输出格式/色彩空间、允许的项目内输出目录。

项目设计分辨率记录UI和游戏画布基准，**不强迫所有人物、装备和技能图都做成同一画布比例**。Creator检测数据仍是来源信息；修改规范不得反向改写Creator设置。

### 资源类别模板

先做少量明确模板，不建立通用插件市场或规则语言。类别继承项目基准，并只覆盖有业务意义的字段。

| 类别 | 与普通图标真正不同的约束 | 最小交付与验收 |
|---|---|---|
| 人物IP | 身份ID/版本、体型比例、脸部/发型/服饰识别锚点、允许变化；视角、表情、动作、镜头、全身/半身裁切 | 先单人物基准立绘/头像，再验证少量视角或表情；脸部/服饰/配色/比例由人工对照确认。图像条件尚未实现前，不承诺自动多图一致 |
| 装备 | 单体图标与佩戴展示分开；轮廓、材质、稀有度语义、持握方向、视角、占画幅、套装识别 | 先装备图标一个模板；在实际背包尺寸与深浅底检查辨识，不直接宣称具备佩戴合成能力 |
| 技能 | 技能语义/元素/职业识别、主色和轮廓、中心焦点、冷却覆盖区、低分辨率辨识 | 先静态技能图标；技能VFX/序列帧是另一类交付，不能用一张技能图标代替 |
| UI | 设计分辨率/缩放策略、组件角色、默认/悬停/按下/禁用/选中等状态、九宫格边界、内容与文字安全区、切图/锚点约定 | 先一套按钮状态和一个面板；九宫格边角/文字留白要在实际布局尺寸检查。完整UI布局、字体排版和Cocos绑定是独立能力 |
| 现有图标 | 固定母图、透明/补底、居中留白、小尺寸轮廓、目标与导出目录 | 保留旧行为，作为迁移回归基准 |

人物立绘、表情图和动作关键帧仍是2D图片交付，不代表3D建模、骨骼绑定或可播放动画。UI类别也不等于“让模型生成一张完整界面截图即可使用”。文字应由受控排版流程处理，不依赖模型画出可用UI文字。

### 单资产需求与身份约束

每次任务记录类别、资产ID/名称、用途、具体画面描述、身份/套装引用、视角或组件状态、该次允许覆盖的尺寸/背景/交付变体，以及验收重点。稳定的人物身份是单独版本化的身份卡，不在每次prompt里任意改写同一角色。

解析规则保持简单：缺省继承、显式字段覆盖、数组按字段约定替换；仅对白名单schema字段解析，不支持任意表达式或脚本。类别必需项、禁止覆盖项和格式冲突在生成前报错，不静默忽略。

## 4. 规范、模型与后处理能力分开声明

规范可以表达“同一个人、正侧背视图、某种材质/光照、按钮九宫格”，但不能让一个不支持相应输入的模型自动做到。

- 身份和多视角一致性：需要实际支持并经过验证的图像条件/身份特征或对应生成流程；固定seed不能被当作身份锁。第一阶段只表达与验收，不宣称已实现模型控制。
- 参考图：先保留当前留证语义。真正接入图像条件前，要明确支持的参考类型、文件/数量限制、如何进入图节点、来源与授权范围、费用和数据去向，并做可观察的输入验收。
- 材质/光照/色彩：当前最多可转成文本约束并做人工美术验收；不能仅凭配置宣称得到准确PBR贴图或严格色值。
- 尺寸与透明：CPU尺寸/alpha验证可以做确定性检查；生成语义、外观一致性和小尺寸辨识需要实际图像验收。
- UI九宫格：当前icon contain导出不是九宫格组件导出。需要组件边界元数据和保边处理；模型图像不能代替布局、字体、安全区和引擎组件状态逻辑。

任务必须显示每项约束是“实际使用 / 仅留证 / 仅导出 / 当前不支持”。不支持的必需约束阻止提交，不能静默退化。不得为了新类别自动切模型、启动GPU、调用云API或增加调用次数。

## 5. 新旧schema与单一权威配置

**第一阶段保留现有文件名和v2，不改名，不双写。** 新schema名称与权威路径在设计确认后决定，文件名不是能力升级手段。

兼容方案原则：

1. 先让宿主、Studio和Next识别新schema，并建立旧客户端拒绝覆盖/降级的门禁，再允许迁移落盘。不能先写新字段，再指望旧编辑器会保留。未知schema必须显示为“不支持”且只读，不能被当作missing/invalid进入修复为v2的写入流程。
2. 旧v2保存是严格白名单，读取又投影固定字段；往v2塞新字段会被拒绝或丢失。必须是版本化合同，不是假装无变化。
3. 明确一个可编辑权威文件；旧文件只作为不可变备份/历史输入。兼容视图和旧图标投影按需计算，不维护两份人工编辑的真相。
4. 迁移前保留原始字节、hash、schema和文件路径；迁移预览逐项展示映射、保留项、冲突和不可表达项，用户确认后CAS/原子提交。
5. v1的全部iconPresets要保留为兼容尺寸变体/模板或明确存档，现有单尺寸迁移草稿不能替代完整预设集合的无损迁移：全部预设尺寸一致才采用共同尺寸，否则为0×0并等待填写。
6. 未知扩展字段保存原始备份与可审查的兼容数据，不把未知内容当作prompt、路径权限或可执行配置。无法可靠保留/解释时停止迁移。
7. 新旧规范都绑定当前projectId与注册路径。工程换源/换路径、并行修改或hash不匹配时保留草稿但不写入。
8. 回滚需要当前文件仍匹配迁移收据hash；恢复原字节与权威指向。已开始的任务仍读其封存规范，回滚不得重写旧任务或UNKNOWN。
