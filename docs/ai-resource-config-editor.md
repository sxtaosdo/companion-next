# 原工程资源配置共用编辑器（Next 0.1.9，0.1.10补参考上传）

## 本片能力与构建边界

侧栏 AI 图标页读到真实工程配置后，在同一个弹窗新建、迁移 v1 或编辑 v2。摘要保持已读取内容；弹窗显示内存草稿、冻结工程身份、原文件 hash、差异及操作回执。没有用浏览器资源规划草稿替代项目规范。

| 构建 | 配置编辑能力 | 实际授权 |
| --- | --- | --- |
| 普通 / Picker / `companion-readonly` | 仅填写、校验、差异预览；不注册保存接口 | 原有构建范围不扩大 |
| `companion-config-editor` | 可注册唯一 `resource-config-save` adapter，仍需原会话和每次用户确认 | 本轮只批准 dot 源码与 fake 验证；尚未批准或执行实机部署 |

新增 `npm run build:companion-config-editor` 输出 `dist-companion-editor`，不并入 `build:companion-static`，不替换此前仅六个新增只读静态文件的交付。HTTP127.0.0.1只是固定传输边界，不是身份或授权证明。新编辑构建部署前须另核原宿主、版本、静态新增范围与项目写入权限；本次没有部署、保存真实配置或变更任何账号/网络安全设置。

## 已核原保存合同

来源 v148 `icon-resource-config.ts:203–262`、`icon-adapter.ts:115–132`、`http-server.ts:581–592`。只有同源 `POST /api/icons/{16hex}/resource-config-save`：

`{config:合法严格v2,expectedHash:原hash或null,approved:true}`。

- `approved:true` 只在用户核对完整目标和差异、明确勾选本次确认后生成。进入页面、打开表单、上次确认、恢复草稿都不自动批准。
- 原后端自己递增版本，不信任客户端提供的新版本。既有未知顶层/嵌套字段、其他Owner归属、路径、参考、画布及冲突由原后端继续保护。
- 原 `expectedHash` 开始及写入前再次核对；临时文件独占创建、fsync、冲突原文件保留/恢复以及后读验证全部仍归原后端。前端不模拟这些磁盘副作用。
- 工程已检测的设计画布只读；没有检测来源时允许填写1..8192。默认单图每边1..4096、总像素≤16M；风格、参考路径、背景、居中留白、Creator/导出目录沿原严格字段合同。0.1.9参考只输入已有相对路径；0.1.10补独立确认的上传模块，成功后仅加入草稿且仍需单独保存配置，详见 `ai-reference-upload.md`。上传不封存为生成任务。
- v1 迁移保留原全部尺寸预设用于核对；默认单尺寸、背景色、尺寸导出目录明确为v2新增，不能把后台推导值当旧已保存字段。
- 无差异的有效v2不重复保存。原配置有可修复问题时仍需原版本/hash，不能把invalid当新文件覆盖。

Adapter没有任意URL、Bearer、写入目录参数、自动重试或其他生成/导入操作。输入128KiB、响应128KiB、4096chunks、20s预算，Cookie同源/禁止重定向/nocache。每个provider单飞；即使请求方停止等待，未结束的底层transport仍占用单飞锁，不能通过取消立即重发。

## 明确回执、冲突和 UNKNOWN

- 只有原 HTTP200、合法valid v2、工程一致、hash已变化、版本为原版+1、内容与提交一致的回执才进入保存已核验。
- 401/403、已核确在写入前的拒绝可标明确拒绝；`RESOURCE_CONFIG_STALE` 标冲突。
- 原 `RESOURCE_CONFIG_CONFLICT / RESOURCE_PATH_INVALID / RESOURCE_CONFIG_INVALID` 也可能发生在写后回读，不能一概视为未写入。`SAVE_UNCONFIRMED`、网络失败、超时、发出后的取消、坏响应及不明服务端错误均为UNKNOWN。
- 不把关闭页面、abort或超时称为撤销。UNKNOWN不会自动再保存；需要用户明确回读。
- UNKNOWN后回读仍是原hash：原请求可能仍完成，继续保护，不据此自动重试。明确STALE回执已结束的同一上下文，允许回读后单独确认采用当前基线；这不会自动再次保存。刷新丢失该回执的内存证据时仍按UNKNOWN保守处理。
- 回读版本和内容与提交目标一致：只标“观察到一致”，不是本次写入归因或原回执。
- 回读另一份内容：标当前配置冲突，保留用户草稿；须单独勾选允许替换后采用新基线。不会静默覆盖未保存修改。
- 成功回执之后，页面再只读刷新摘要；这次读取失败也不会伪造当前摘要。保存请求返回前如果又有内存草稿变化，保留新内容并显示仍有未保存修改。

## 保存保护与页面生命周期

表单冻结完整id/name/path、登记来源、reader、writer和原配置hash。输入变化立即撤销本次确认；源/目标变化使原确认失效。A→B→A、等待摘要期间修改、关闭、离页、provider撤销、晚回执都要重新核对，不把旧请求应用到新工程。

在发送保存前，sessionStorage保存有界待核对记录，只有工程ID、expectedHash、目标版本、目标内容规范化SHA摘要。没有表单正文、路径、token、Cookie或图片。保护记录写入失败/无法回读/损坏时禁写，表单仍可编辑；本页不提供清记录绕过按钮。每页最多32条、16KiB；每工程至多一个未核对保存。

该记录用于保留刷新后的未知操作，不是浏览器配置草稿。草稿正文只在页面内存，关闭浏览器会丢失。离页仍保留内存草稿，可通过“查看保留的编辑草稿”找回；查看不恢复权限。只有原完整绑定和明确新读取能够恢复可操作上下文，变化基线继续要求确认采用。

跨tab不共享表单确认，最终并发写入由原服务器expectedHash冲突保护；不声称UI内存锁能替代原文件CAS。任何实机多tab行为仍需真实验收。
