# 两来源整合检查点

## 当前可以操作

在资源规划建立草稿后，第 2 步与第 3 步使用同一来源选择：未选择、本地 ComfyUI、Codex 原生。选择仅改变计划的 `generationSource`，不改变项目规范、冻结快照、需求、尺寸、批次和 Owner 保护。项目 / 示例或真实模式互相隔离；切换页面保留，刷新仍需先导出 JSON。

新计划默认 `unselected`，不会暗中选择付费服务。旧版 schema 1 缺少该字段时显式恢复为 `unselected`；字段存在却为 null、任意地址、对象、token 或其它枚举均拒绝。恢复仍检查原有完整结构、大小预算、同项目与模式、规范绑定、Owner 项及备份边界。

## 能力与证据的边界

- Codex 原生：会话生成 / 人工回收，半自动。2026-10-11 Owner 在独立会话确认本机原生测试图“可以”；收到单次原生生图 → 1254 RGBA 原图 → 既有 LANCZOS 1024 透明 QA PASS 的报告。这只是独立样本验证，不是当前网页或本计划执行证据。此工程没有运行该测试或读取其图片。网页自动提交、会话结果协议和文件回收未核实，不宣称可一键执行。
- ComfyUI：本网页没有生成服务连接。现有 v133 只读适配器只有 `/api/projects`、`/api/status`，并无 ComfyUI 作业 / 模型 / GPU 协议。此状态不否认另外的既有本机流程；接通前需要其真实协议与版本证据。
- 来源均没有自动执行方法，UI 提交按钮禁用。没有外部生图请求、凭据读取 / 存储、网络代理或新增依赖。
- 选定参考图后，Codex 会话路线会将素材交给 OpenAI；本地 Comfy 路线拟在本地处理。此网页不上传任何图，也不取得发送权限。实际执行端必须确认选定素材、许可和发送范围。

## 统一离线交接

`src/domain/generation-handoff.ts` 构建 `companion-generation-handoff`：

1. 来源及当前真实能力说明。
2. 原资源 manifest，保留完整规范绑定 / 项目 / 需求 / 批次和全零计数。
3. 只为已编批、非 Owner 保护需求列出预期母图尺寸、PNG / 透明要求及同图派生。预期尺寸不是模型实际输出尺寸；实际像素尺寸须在回收后独立核验。
4. 参考选择和裁切保持 `not-attached` / `not-recorded`，不假造参考素材。
5. 输出回执保持 `awaiting-external-files`；文件列表为空，技术与视觉均未检查，保存 / 导入 / 绑定为 false。
6. 要求后续真实证据：来源 / 会话或工作流版本、需求和规范 ID、实际文件及 SHA-256、尺寸和 alpha、母图派生关系、Owner 批准，以及独立工程交付记录。

该 JSON 是出站人工交接草稿，不是执行 payload、产物导入合同或可恢复计划。计划恢复入口会拒绝它。嵌套原 manifest 与交接包分别满足 512 KiB 预算，失败不修改原计划。

上述出站交接包不接收产物或信任任意成功声明。新增的本地文件回收使用独立 `companion-generation-receipts` 清单，实际读取用户所选 PNG 字节和 SHA-256，保留冻结上下文，见 `generation-receipts.md`。缺少可核协议前不能把用户填入的“通过”当作自动 QA，也不能给空回执补上假文件、UUID 或成功状态。

## 共用流程与未完项

两来源共用：规范 / 需求 → 参考选择与裁切 → 母图 → 技术 QA 与人工审阅 → 已批准同图派生 → 保存 → 导入 → 绑定 → 运行。

来源选择检查点实现交接数据；后续人工文件回收已可记录真实所选字节，但没有来源服务自动回收、参考裁切、生成、批准或工程保存。下一步需分别核实真实来源协议和产物证据，再接入同一审阅 / 导入边界。新的 GitHub 项目、依赖、持久权限或计费 API 不在本片范围。

组件 DOM 与离线合同测试可运行；真实浏览器文件下载、视觉，以及两来源真实端到端执行尚未验收。未重试先前受限 Chromium IPC 路径。
