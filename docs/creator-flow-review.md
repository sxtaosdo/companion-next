# 当前0.1.18页面核对要点

这是组件DOM和文字交互清单，不是运行截图。当前项目页标题为“工程”，说明收进问号；原导航、连接按钮和工程/日志/调用三个入口保留。

- 首次打开没有业务请求；连接后显示真实返回状态。Dashboard说明只提示一次，不每次轮询刷屏。
- 点击“启动 Creator”直接发送原start；ready时“打开 Creator”直接focus。没有二次确认框，也不出现成功后的常驻回执卡。等待期间按钮loading且防重复。
- 传输清理完成、原目标和来源仍一致后提示收到回执，再读取状态。超时/失败保持简短提示与原详情问号，日志/调用仍从原入口查询；旧回执不在返回页面时重复toast。
- 停止/重启/目录/移除仍保留原确认；安装接入另开原向导，五项选择不默认勾选。未知任务或清理挂起关窗后，任务ID/完整路径/诊断仍在状态问号中可读。
- 问号可键盘聚焦，Escape收起；无HTML执行，不把回执当ready、窗口或磁盘结果。

源码细节见`compact-project-ui-018.md`。真实浏览器视觉/窄屏由部署消费端继续验收。以下保留0.1.14–0.1.16历史展示，其中启动二次确认和常驻回执已被0.1.18明确取代。

# 正常工程模式可审查展示（0.1.15，含0.1.14首片）

以下历史展示按当时Vue组件与离线DOM回归逐项列出实际页面内容，不是实机截图。未运行Windows、Creator或真实接口，示例目标仅用于fake测试。审阅入口：`/projects`，构建 `companion-workspace`；旧readonly模式不出现启动/聚焦按钮。

## 1. 首次打开

- 顶部「工程状态与 Creator 操作」
- 主按钮「连接工程服务」；尚未连接，不展示示例或推断已停止
- 提示状态读取会查询Bridge，更新后台状态和诊断日志；未启用Dashboard/CIM发现
- 初始业务请求0次，原服务认证由宿主处理

## 2. 点击连接后：已停止工程卡

合成目标「待操作工程」，ID `0123456789abcdef`，路径 `D:\Fixture\Game`。

- 状态「已停止」，当前Creator版本/工程要求版本分别呈现，缺失不补造
- 主按钮「启动 Creator」，次按钮「聚焦 Creator」；放在卡片折叠区域外，折叠不隐藏核心入口
- 「刷新真实状态」「启用实时更新」为真实动作入口，不用CLI说明替代
- ready工程主按钮改为「打开 Creator」，发送的原动作是focus；启动中/等Bridge/停止中会说明为何禁止重复启动

## 3. 点击启动：核对弹窗

标题「启动 / 打开 Creator」，逐项展示：

- 工程名称、完整ID、路径
- 最近真实状态
- 读取来源、操作来源、快照时间
- 说明可能打开应用/导入Dashboard工程记录，等待Bridge
- 明确本操作不安装/更新Bridge，不配置Codex；未接入工程仍须另行完成安装接入
- 明确关闭/停止等待不取消后台动作，超时/断线不自动重复启动
- 按钮「关闭」「确认启动 / 打开此工程」

确认期间暂停工程自动轮询，避免用户读说明时被3秒轮询打断；日志/事件流仍工作。手动刷新或真实工程/来源变化会撤销原确认，要求重新核对。

## 4. 已发出与回执

- 发出后冻结目标、原动作和来源仍留在弹窗；聚焦不会错误变成启动标题
- 等待中「停止等待」「关闭并停止等待」，无第二个确认按钮
- 后台200只显示原回执；保持原上下文时再读工程状态，不把启动回执当ready，不把聚焦回执当已看见窗口前台
- 结果未知显示原工程与UNKNOWN说明，保留在页面上；需重新真实读取原状态并再次确认，不会自动重发
- 已确认回执的清理期间若离页/换来源，不自动回读新页面或新来源

## 5. 停止与重启（0.1.15增量）

- 已连接的正常模式卡片新增「停止 Creator」「重启 Creator」，沿用完整目标/来源确认；不会跳过未保存检查、发送强制关闭参数。
- 停止弹窗提示先保存Scene/Prefab，前端没有核实未保存状态；确认按钮「确认停止此工程」。回执含「不证明操作系统进程已退出」，卡片仍显示再次读取的真实状态，不直接改成已停止。
- 重启弹窗说明原后台流程和无Bridge时可能拒绝；确认按钮「确认重启此工程」。重启回执不自动宣告ready。
- 无Bridge错误码不能确定发生在检查前还是重开后，回执保留两种可能和核对提示；未保存文本提示仍保留UNKNOWN。
- 0.1.14冻结候选与这份0.1.15源码分开，部署审批和实际启停验证没有从前版继承。


## 0.1.16 增量DOM审查路径

以下描述对应真实Vue/ElementPlus组件的jsdom离线测试，不是浏览器截图或原生窗口验收：

1. 正常工程卡展开 → 打开目录：显示冻结ID/路径/来源、只发送ID与窗口可见性限制。取消不发请求；确认后保留原路径回执并重新读取。
2. 正常工程卡展开 → 移除登记：显示不删工程文件/不停Creator、不原子/无undo、工具绑定与重新登记full风险。危险按钮文本为“确认移除此登记与工具绑定”。
3. 回执独立保留原目标；原行消失不抹除操作记录。removed:false明确保留，本次请求不能冒充已移除。
4. UNKNOWN后“重读登记与状态”只读原来源；显示存在/缺失/同ID变更和时间，不改原结果，也不假定绑定清理。来源变化禁用旧回执按钮。
5. 只读模式不出现两管理按钮；在途操作同时禁用目录、移除与启停动作。停止等待不取消后台操作。
6. stop/restart新增旧后台Boolean转换风险说明，不能承诺异常空值全部被拦截；自行保存仍为必要使用提示。

真实窄屏/桌面像素布局、键盘焦点、文件管理器及宿主Cookie交互仍待浏览器/本机验收。

## 0.1.17 增量 DOM 审查路径

本节对应 `tests/project-setup-ui.test.ts` 中真实 Vue / Element Plus 的 jsdom 交互，未生成或冒充浏览器截图。

1. 工程页“添加已有工程”：手动绝对路径 → “核对仅登记”显示路径 / 来源 → “确认仅登记此路径”。返回后同时显示输入与后台规范路径；安装步骤没有自动勾选或提交。
2. 工程卡展开“安装 / 更新接入”：已登记工程身份和路径、三项作用与两项风险确认均直接可见，默认五项都未选。
3. “核对完整安装接入”仅全部主动勾选后可用；确认区仍显示精确工程 / 来源 / 202 和后台不可取消提示。改选项或手动刷新即撤销确认。
4. 发出后任务卡显示原目标、已接受但未完成、任务 ID。六项工程动作和新登记受同页锁限制。阶段文案显示后台阶段而非全流程成功。
5. “关闭向导”保留页面任务卡，停止自动读取；“继续读取此任务”只读已知 ID。UNKNOWN 没有 ID 时保持锁定，不提供自动重发。错误不会被清空成已完成。
6. 后台 complete 显示“不能据此保证本次请求选项已采用、Creator 已就绪或 Codex 已写入”；failed 显示部分改动与没有整体回滚。
7. 原只读 / 配置编辑 / 问答 / Picker 构建没有此写能力注册。源码 normal 模式不代表已获部署或持久配置实机执行许可。

真实桌面 / 窄屏排版、键盘焦点、原宿主会话、注册 / Bridge / Codex 落盘与跨客户端任务并发仍待逐项验收。
