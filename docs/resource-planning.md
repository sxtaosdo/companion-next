# 资源需求、批次规划与执行前预检

本片延续已批准 Vue / Element Plus 栈，未引入新依赖、GitHub 方案或外部接口。原 Windows Companion 保持冻结。

## 已实现入口

游戏资源 → 第 2 步“资源规划”。用户显式建立内存草稿后：

1. 冻结当前项目规范的完整快照、版本和风格名称引用。
2. 添加资源名称、类别、关联页面、用途、优先级、PNG / 透明要求、默认尺寸、Owner 保护与补充验收条件。
3. 默认只规划一个尺寸。附加尺寸必须显式启用并确认来自同一已批准母图，只能保持比例缩小，不放大、不裁切、不重新推理。
4. 选择 1–32 项需求建立串行计划批次；同一需求不能重复编批，Owner 保护项不能编批或派生。
5. 预览、复制或下载 JSON manifest。全部保持“草稿 / 未批准 / 未提交 / 未生成”。
6. 执行前预检展开“母图计划 → 人工视觉批准 → 同图缩放”依赖和缺失条件。

规划不要求已批准样板或真实服务。真实生产仍必须满足 Owner 批准、参考 / 模型许可、已登记工作流、服务可用性、目标工程交接等条件。

## 本地与数据边界

- 此资源计划仅驻留当前浏览器页面内存，不写 localStorage、项目 JSON 或 Git。它与已有规范的本地持久草稿是两种明确区分的记录。
- 页面内导航可以保留计划；刷新、关闭页面会丢失，需先导出备份。支持本合同 JSON 的严格导入恢复；仍不是自动持久化系统。
- 不自动导入示例资源或真实资产。切换示例 / live 模式或项目后使用不同计划，互不混用。
- 不静默覆盖已有计划，不在规范改变后自动重绑定。即便版本文字未变，只要规范任一字段变动，新增需求和编批均暂停。
- 原计划可以导出留存；如需使用新规范，先导出、刷新，再开始新草稿。
- 未编批且未受 Owner 保护的需求可以编辑或移除；编批后必须先明确取消对应的本地批次，再修改需求。取消批次保留需求，不撤销任何真实任务。审批操作、任务执行与重试尚未接通。

## 类型合同

`src/domain/resource-planning.ts`：

- `ResourcePlan`：项目 / 模式、不可隐式重绑的规范与风格快照、需求、批次和全零执行计数。
- `ResourceRequirement`：默认尺寸和可选同图派生，均绑定相同 `specBindingId`；八条技术 / 视觉 / 工程验收条件均为 `not-checked`。
- `PlannedBatch`：同项目、同规范 / 风格引用的一组需求，串行、未批准、未提交。
- `PlannedDerivative`：来源为当前需求同一母图，`resize-approved-master`，新增推理数固定为 0。
- `exportResourcePlan`：导出前做一致性和体积检查；`parseResourcePlan` 对外部 JSON 做独立严格校验，不把 TypeScript 类型当作外部数据证明。

资源上限为每计划 200 项、50 批，每项最多 8 个派生尺寸。这些是本片防误操作预算，未做 GPU 吞吐承诺。

## 执行前预检

`src/domain/resource-preflight.ts` 不包含 transport、工作流 payload、模型选择或执行方法。

- `localValidation: passed` 只证明计划结构满足合同，不是资源验收。
- `executionStatus` 永远为 `blocked-not-started`。
- 母图计划计 1 次拟推理；人工批准关卡和全部尺寸缩放计 0 次新增推理。
- 所有节点都是 `not-started`，实际提交和实际生成固定为 0。
- 额外尺寸依赖人工批准关卡，人工批准关卡依赖母图生成，不能跳过。
- 示例源、空批次、规范过期以及缺少批准 / 许可 / 工作流 / 服务 / 工程证据均明确列出。

## 验证与尚未验证

本片纯逻辑和 Vue 组件 DOM 回归覆盖尺寸、绑定隔离、Owner 保护、批次重复、假执行状态拒绝、规范漂移、导出和预检依赖。与原 117 项测试一并执行，最终结果见 `validation.md`。

真实 Chromium 渲染与截图仍受当前环境 IPC 限制，未重复绕过。未运行 Windows、ComfyUI、Creator、Bridge 或真实 GPU 推理；没有实际资源产物。

## 下一阶段的真实阻塞

可以继续从本合同细化已登记工作流的具体输入 / 输出映射，但必须先取得真实协议和版本证据；不能凭空指定模型、安装新方案或把计划当作生成结果。接通真实生成还需要 Owner 批次及风格批准、输入素材 / 许可、目标服务与工程授权。遇到新的 GitHub 方案或依赖候选，先向 Owner 说明并征得同意。

## 恢复与修改检查点

- 仅导入完整的本合同 JSON，最多 512 KiB；逐层拒绝未知字段、缺失字段、错误类型 / 状态、假执行或验收结果、重复 / 缺失引用及伪造统计。成功恢复不会调用任何外部地址或写入路径。
- 导入必须匹配当前项目 ID、名称和示例 / live 模式。已冻结的规范快照原样保留，不能在恢复时自动重绑定。
- 当前已有草稿时，必须在弹窗显式确认替换。原草稿保存在本页可导出的备份列表，最多 5 份；到达上限时拒绝继续覆盖，不自动淘汰旧备份。
- 已有 Owner 保护项不得借由导入被改写、移除或解除保护。
- 备份也是内存数据，刷新会丢失。需要保留时先导出备份；不是写入项目配置或永久保存。
- 编辑保持需求 ID 与规范绑定不变，所有派生仍引用该需求母图；修改含派生尺寸的需求须重新明确确认同图缩放。
- 已编批需求不能直接编辑 / 移除；先取消本地批次，需求保留，然后可重新编批。需求移除和批次取消都要求界面确认。
- 同时读取多个导入文件时，以最后选择为准；项目切换会作废尚未完成的文件读取。

导入除了检查原始输入大小，也检查标准重新导出的大小；构建 / 修改计划同样限制到可导出的 512 KiB 预算，避免留下不可备份草稿。相同规范绑定 ID 永远不能指向不同快照；有 Owner 保护项时禁止任何规范重绑定。文件读取期间恢复按钮禁用，失败不复用旧候选。

## 生成来源与统一交接

计划新增 `generationSource`：默认 `unselected`，可选 `comfyui` / `codex-native`。切换只改变该元数据，不改规范或 Owner 项。旧 schema 1 缺来源字段恢复为未选择；新来源值同样受严格枚举校验。来源可随计划导出 / 恢复。

统一交接 JSON 保留原 manifest，列出预期输出和空回执；始终未提交、未回收、未验收。Codex 使用会话生成 / 人工回收半自动边界；ComfyUI 在本网页协议待验证。两者共用参考裁切、审阅与交付条件，但本片没有实现真实参考文件或结果输入。见 `generation-sources.md`。
