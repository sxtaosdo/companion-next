# 工具预设页面草稿（0.1.11）

## 可用价值与边界

入口：帮助 → 工具清单 → 打开本地预设草稿。复用现有 Vue / Pinia / Element Plus，没有依赖或新后端。

- 克隆已成功读取的 core/full 或自定义预设为新的 `preset-UUID`，来源、原 ID/名称、原时间和工程上下文保留在内存说明中；JSON导入没有原工程信息，不能用导入时当前工程冒充来源。内置项和当前服务选择不变。
- 编辑本地名称、基础范围，以及每个工具的跟随基础 / 显式启用 / 显式禁用。临时空名或重名保留输入但禁止导出，方便完整重命名。
- 导入原兼容 JSON 到页面草稿。解析预览不修改原草稿；非空集合替换需明确确认，保留一次可交换恢复的内存备份。移除和另建 ID 副本同样保留备份。
- 页面离开/弹窗关闭保留草稿与备份，但撤销已确认读取上下文；刷新/关闭浏览器丢失。导出并保管 JSON 后可再导入恢复。未使用 localStorage/sessionStorage，也不自动上传或存盘。
- 新副本解决导入文件与已读宿主同 ID/名称冲突必须用户明确操作，不能偷偷改身份。有效 JSON 可在未连接时导入保留；工具目录未知时不允许把它作为已核验草稿导出。
- 本片不调用宿主 create/update/import/delete/assign，不注册 MCP，不改变工具权限。目录中的 read/write 是旧版描述标签，不是授权证明。

## 原合同证据

已核自有 v148 HEAD `f6dcac804fb9ad806e8094594c7820a71cfab7b8`：`mcp/src/companion/tool-preset-store.ts` SHA-256 `5b34ed4c3f4bf8ac947eea723649a0c7bd20ac64f93dd7fb9d1b32e72f8ec402`。该源已在既有批准参考闭包中，不引入新 GitHub 项目。

原导出/导入封套只有 `schemaVersion:1`、`presets`；每项严格七字段：`id,name,baseProfile,enabled,disabled,builtIn,updatedAt`。`projectSelections` 只属于持久存储，不可混入此 JSON。页面来源说明也不混入兼容导出文件；跨浏览器恢复仅恢复七字段方案，来源未知如实标示。原 store 用严格 schema 后再规范化及校验工具全集/重名/容量，不允许保存内置项。

本地增加保守预算：UTF-8 输入与标准两空格导出均≤1MiB、最多20份、每列表≤512工具、深度≤8。先检查标准导出预算才允许替换，避免能导入却无法备份。拒绝未知字段、错版本、危险控制字符、重复 ID、case-insensitive 重名、工具重复/同时启禁与无效时间。不静默去重或抛弃未知工具。内置 ID core/full 与同名英文自定义名称禁止；合法中文“核心工具/全部工具”自定义名称仍按原合同允许。

本地比原后端更严格的标识字符/长度和安全预算明确沿用既有已核读取投影；不能声称接受后端可接受的任意扩大数据。现实现的工具目录成员均满足原已核格式。

## 最终导出与上下文

最终导出重验完整集合、当前工具目录及当前已读自定义预设，包括当前宿主项自身的失效工具。对照原 import，ID/name不可冲突，宿主已存 custom 与拟导入合计≤20。页面允许最多20份本地草稿；即使宿主已满仍可本地整理，但不能把它导出为可直接导入该宿主的无冲突包。

每次来源 identity、工程 ID、列表/目录引用或内容、读取中/失败状态变化都撤销确认及 prepared handles。重新成功读取后须显式核对快照；克隆当前已读来源是明确采用该快照的操作。导出不是实时 CAS 证明，即使快照核验通过，用户未来导入宿主时仍必须由原服务器重新校验。

准备下载时冻结修订号和上下文；nextTick 后、创建 Blob 后、click 前均重新核验。URL 在成功或失败时都回收；文案只报告请求浏览器下载，不能证明磁盘文件已保存。新文件选择立即清旧候选/确认，文件读取期间禁恢复；文件过大/失败/晚到/换来源/关闭均不得恢复旧候选。
