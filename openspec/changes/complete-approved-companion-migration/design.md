# Design

## Context

当前维护源码与唯一32180已生效状态版本为1.3.183。34项矩阵是差异基线，AGENTS与source-and-reuse-policy仍权威。旧宿主公开接口已具备裁剪、交接及确认删除合同，优先接线。测试工程已登记，但当前Bridge不可达、任务库为空且adoptionSources为空，不能把旧32181任务当作当前任务。

## Goals / Non-Goals

**Goals:** 补齐获批四项，维护原鉴权、来源/任务/图片绑定、UNKNOWN不重放；真实验收经后台UI并记录完整回执。

**Non-Goals:** 不改已批准布局、日志手动查询、账号网络安全，不新增模型/UI人物生成或参考图入模，不创建32181，不用脚本直接操作Creator。

## Decisions

- 提示词复用现成SetupCompletionUsage和构造函数，不自建平行模板体系。
- 交接与裁剪复用旧公开合同、当前same-origin fetch及原store保护；组件不得ambient fetch或直接调用Creator。
- 普通预设删除与关联回退使用两个显式入口；恢复能力不等于授权删除现有用户数据。
- 同时核对真实DOM与契约，styles/事件须真实浏览器；未知、切换、晚到结果保留测试。
- 本地OpenSpec1.14.3装在D盘，仅项目新增工作流与文档，无服务、全局PATH或MCP变更。包与源记录写入交付证据。
- 采用既有图片需要原受控来源列表；若必须新增固定PNG/catalog/evidence绑定与服务级重启，先列精确目标和风险，不能临时放开任意路径。

## Risks / Trade-offs

- 旧API无CAS不能假称原子并发保护，现有预览/确认与冲突检查保留。
- 当前来源列表为空，真实导入可能受配置前置阻塞；不靠搬迁整个旧任务库解决。
- 实际安装可能部分完成；超时先查原任务，不能整体重跑。只操作既有测试工程。
- OpenSpec结构校验只验证文档，不是业务验收；未测项保持unchecked，不以完成比例伪装全闭环。
